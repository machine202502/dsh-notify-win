# dsh-notify-win (форк)

Уведомления Windows для DeepSeek Harness: нативный тост и мигание значка на панели задач,
когда ход завершается, падает или требует вашего участия.

> **О форке.** Форк [Andyqwe44/dsh-notify-win](https://github.com/Andyqwe44/dsh-notify-win)
> (MIT). Обработка событий, тосты, тосты вопросов и подтверждений, переход по клику и
> мигание панели задач — работа исходного автора; исходный `LICENSE` оставлен без изменений.

## Что меняет форк

- **Свой сигнал уведомления** — `lib/notify.wav` (калимба) проигрывает резидентный хелпер
  через `winmm!PlaySound`, поэтому тост сохраняет системный вид, но звучит по-нашему.
- **Без двойного звука** — собственный `<audio>` тоста выключен; играет только встроенный
  сигнал.
- **Сигнал начала хода** — `lib/start.wav` (двойной удар колокола) звучит, когда агент
  берёт ход в работу. Это только звуковое уведомление: операция `sound` в хелпере
  проигрывает сигнал и не создаёт тост, поэтому она не зависит от политики фокуса тостов и
  никогда не включает мигание панели задач.
- **Иконка в стиле приложения** — `icon.svg` в палитре плагина; хелпер регистрирует её для
  AppUserModelID.
- **Готовый хелпер в пакете** — `lib/dsh-toast-question.exe` лежит в репозитории и
  поставляется вместе с пакетом, поэтому установка с GitHub не требует .NET SDK.

Во всём остальном поведение совпадает с upstream; полная таблица событий и протокол
тоста-ответа — в его README.

## Требования

- Windows 10/11;
- .NET 10 Desktop Runtime (все тосты показывает хелпер; запасного пути через PowerShell
  нет).

## Установка

В `~/.dsh/profiles/desktop/package.json`:

```json
{
  "dependencies": {
    "@machine202502/dsh-notify-win": "0.5.3-fork.1"
  },
  "dsh": { "profile": { "bundles": ["…", "@machine202502/dsh-notify-win"] } }
}
```

Затем перезапустите DSH. Плагин запускает `dsh-toast-question.exe` на всё время своей
работы.

## Настройки

Любое из этих значений переопределяется в профильном `cordis.patch.yml` в секции
`- id: dsh-notify-win`:

```yaml
- id: dsh-notify-win
  config:
    language: auto                 # auto | ru | en | zh
    doneTitle: 'Ход завершён'
    doneBody: '…'
    questionTitle: 'Нужен ваш ответ'
    questionBody: '…'
    dedupMs: 1500
    questionToastDuration: short   # short | long
    doneToastDuration: short
    approvalToastDuration: long
    answerPendingTimeoutMs: 30000
    showProject: true
    notifyWhenFocused: true
    notifyOnTurnStart: true
    startSoundFile: start.wav
    notifyOnCancel: true
    notifyOnError: true
    includeErrorCode: true
    helperLog: ''
```

`notifyWhenFocused`, `notifyOnTurnStart`, `notifyOnCancel`, `notifyOnError`, `showProject`,
`includeErrorCode`, `language` и строки `*Title`/`*Body` необязательны; значения по умолчанию
лежат в `lib/index.js`.

## Языки / Languages

Тексты тостов по умолчанию поставляются на трёх языках: **ru**, **en** и **zh**. Это все
заголовки и тела (задача выполнена, контекст сжат, подтверждение, вопрос, отмена, отмена
хуком, лимит вывода, блокировка хода, ошибка, неизвестная остановка, сбой сжатия), а также
подсказки к ошибкам, суффикс кода сбоя и суффиксы повторов.

```yaml
- id: dsh-notify-win
  config:
    language: auto   # auto | ru | en | zh
```

`language: auto` (значение по умолчанию) следует системной локали: сначала
`Intl.DateTimeFormat()`, затем `LC_ALL` / `LANG`, а если ничего не подошло — английский.
Локаль, начинающаяся с `ru` или `zh`, выбирает соответствующий набор; всё остальное —
английский. Явно заданные `ru`, `en` или `zh` важнее системной локали.

Любой текст по-прежнему можно переопределить по ключу в настройках профиля, и такое
переопределение всегда важнее языковой таблицы:

```yaml
- id: dsh-notify-win
  config:
    language: ru
    doneTitle: 'Готово'
    maxTokensBody: 'Достигнут лимит вывода — отправьте «продолжай», чтобы дописать.'
```

## Звук

Сигнал тоста — `lib/notify.wav` рядом с хелпером: ~0,72 с, моно, 44,1 кГц, −13 dBFS с
плавным затуханием. Сигнал начала хода — `lib/start.wav`: два удара колокола A5 с интервалом
0,22 с и хвостом ~1,2 с, поэтому начало хода безошибочно отличается от сигнала завершения.
Оба файла ищутся рядом с хелпером: замените файл, чтобы изменить звук, или укажите
`startSoundFile` на другой встроенный сигнал. Если файла нет, играет системный звук
уведомления.

## Сборка

Хелпер написан на C# (.NET 10). Чтобы пересобрать:

```bash
npm run build   # dotnet publish → копирует dsh-toast-question.exe в lib/
```

Нужен `dotnet` в PATH (или переменная `DOTNET`, указывающая на SDK).
